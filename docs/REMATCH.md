# 한번 더하기

## 확정된 동작

- 게임 종료 후 기존 결과 화면의 10초 동안 `한번 더하기`로 재참가를 신청한다. 신청은 중복 반영되지 않으며 마감 후에는 신청할 수 없다.
- 마감 시 신청했고 여전히 해당 방에 참여 중인 사용자만 같은 새 대기방으로 이동한다. 신청하지 않은 사용자는 기존처럼 로비로 돌아간다.
- 1명부터 방을 만들고 정원은 `max(4, 신청 인원)`으로 정한다. 4명 미만이면 추가 참가자를 모아야 한다. 기존 최소 4인·최대 6인 규칙은 유지한다.
- 기존 방장이 신청했다면 방장을 유지한다. 신청하지 않았거나 나갔다면 남은 재참가자 중 한 명을 임의로 선정한다.
- 새 방은 기존 제목을 사용하는 **공개 대기방**이다. 이전 비밀번호·채팅·결과·역할·손패는 넘기지 않는다. 추가 참가자는 기존 로비/방 코드 입장 기능을 이용한다.
- 방장만 준비 완료로 시작하고 나머지는 다시 준비해야 한다. 자동으로 게임을 시작하지 않는다.
- 신청 후 나가기·탈퇴 등으로 이전 방의 참여 참조가 사라진 사용자는 제외한다. 유효한 신청자가 없으면 새 방을 만들지 않는다.

## 처리와 저장

종료된 방에 최대 6개의 UID 배열 `rematch`만 보관한다. 접수 중에는 새 방을 미리 만들지 않는다. 게임 비밀과 개인 손패는 기존처럼 종료 즉시 삭제한다.

기존 10초 종료 정리 시점에 Firestore 트랜잭션 하나로 새 방·기본 서버 설정·신청자의 참여 참조를 기록하고 이전 방을 정리한다. 여러 클라이언트가 동시에 정리를 요청해도 이전 방을 다시 읽고 재시도하므로 새 방은 하나만 생성된다. 미참가자의 참여 참조는 해제한다. 별도 신청 컬렉션·이력·유료 스케줄러는 추가하지 않는다.

접속자가 전부 닫혀 있으면 다음 bootstrap/create/정리 요청에서 처리하는 기존 정책을 따른다. 새 방은 기존 방과 같이 24시간 미활동 후 정리 대상이다. 기존 게임 종료 화면을 열어둔 구버전 클라이언트에는 새 버튼이 표시되지 않으므로 업데이트 후 새로고침한다.

## 검증

- 단위/API 28개: 종료 전/비참가자/마감 후 차단, 한 명 재참가, 중복 신청, 4/5/6인 동시 신청·정리, 방장 유지/재선정, 준비 초기화, 나가기/탈퇴 사용자 제외, 재경기 시작을 포함한다.
- Auth + Firestore + 운영 HTTP 에뮬레이터 5개: 4/5/6인 전체 게임 뒤 기존 방장을 제외한 동시 신청, 중복 신청, 동시 bootstrap, 동일한 새 방 배정과 기존 방 정리를 확인했다. SDK 네트워크 중단·복구 후 채팅 수신과 재인증·탈퇴 회귀도 통과했다.
- 로컬 Chromium 4/5/6인: 결과 버튼·신청 완료·10초 후 미신청 방장 로비 복귀·신청자 동일 새 방 이동·새 방장 배정을 확인했다. 390×844 모바일 결과 화면과 가로 넘침 없음도 확인했다.
- 명령: `npm test`, `npm run test:integration`, `KRAKEN_REMATCH=1 KRAKEN_PLAYERS=6 npm run test:browser`, `npm run build`.

운영의 서로 다른 Google 계정 4~6개로 실행한 검증은 아니다. 브라우저 검사는 로컬 데모, 인증/DB 검사는 `demo-kraken` 에뮬레이터를 사용했다.
